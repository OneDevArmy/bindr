## Agent Kernel Overview

The micro-kernel in `src/core/kernel.rs` supervises each agent as an isolated Tokio task. The kernel pushes `IntentEnvelope` messages over bounded `mpsc` channels and receives `KernelEvent` updates via a broadcast bus. Agents publish status through the provided `AgentBroker`; they cannot talk to each other directly. On panic, the kernel emits a `Panicked` lifecycle event, waits for `KernelConfig.restart_backoff`, and respawns a fresh agent instance until `max_restarts` is exceeded. Caller code can subscribe to kernel events and dispatch intents without sharing internal state.

`src/core/agent_runtime.rs` now wires per-mode factories directly into the kernel. It subscribes to `KernelEvent`s so conversation entries persist via the `SessionManager`, tool reviews and approvals flow through the broadcast channel, and environment warnings surface without blocking the UI loop. Incoming JSON tool envelopes (e.g. `{ "tool": "web_search", "args": { ... } }`) are parsed, validated via `ToolDispatcher`, and executed through `ToolExecutor`—either immediately or after the user approves the queued request. `AgentManager` remains the façade exposed to callers, but every operation is routed through the kernel-backed runtime.
